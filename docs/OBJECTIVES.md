# Target problems and delivered scope

The initial use cases were document reading, research records and everyday assistance on local hardware. The design developed toward a continuing individual model that can communicate, judge and work. This table distinguishes objectives, implementations and remaining evidence.

| Problem | Design direction | Delivered implementation | Remaining scope |
|---|---|---|---|
| Decision/language computation is loosely coupled | Preserve direct judgment and open language within shared computation | Four core visits, decoder feedback, shared experience and candidate encoding | Stable cross-task benefit and contribution of each connection |
| The project needs explicit, connected brain-inspired functions rather than names alone | Implement distinct recurrent populations, memory levels and modulatory connections | Regional circuit, hippocampal pathways, prediction, modulation and drive states | Checkpoint-aligned causal evidence and the limits of biological correspondence |
| Incomplete evidence provides no ready-made answer | Form useful, revisable intuition and testable directions | Recurrent alternatives and same-model Spark generation/ranking/revision | Long-term utility and effective research discoveries |
| Long work loses instructions and experience after repeated compression | Maintain identity, goals, exact provenance and retrievable experience | Neural state, role/source records, journal and paged storage | Coverage, latency and reliability in large heterogeneous tasks |
| KV context is treated as all memory | Separate the language working view from persistent experience and sources | Layered experience, restoration, retrieval and historical million-token checks | Broader retention, correction and aggregation |
| Per-record limits damage long material | Preserve full records across pages | Paged sources and durable journals | Storage exhaustion and long-term archive maintenance |
| Thoughts mix with facts and old conclusions lose revision links | Track epistemic type, origin and revision | Fact/hypothesis/intention/goal types and correction/retraction links | More complex source conflicts |
| Goals, judgment and language are disconnected | Share goal representations and select goals/actions jointly | Joint head, permission/resource constraints and result feedback | Stable multi-goal, long-task behavior |
| All initiative is prescribed by external scheduling | Compute drives and action choice inside the model | Drive state, initiative readouts and idle computation opportunities | Sustained useful thought and spontaneous communication |
| Adaptation loses old abilities or experience | Learn with retention constraints and persistent individual state | Joint offline interfaces, deployed output-adapter learning and restoration | Longitudinal gains, forgetting and rollback evidence |
| Technical progress is tied to one small backbone | Preserve core interfaces and experience contracts across upgrades | Backbone adapters, binding and migration interfaces | Effective learned-cognition and experience transfer |
| Local deployment has limited compute and memory | Start small and measure quality/cost | Q8_0 default, GPU language path and CPU cognitive/lifecycle work | Broad real-task quality and time-cost comparisons |
| Research-machine dependencies prevent reuse | Ship weights, source and a common execution entry | Transformers/GGUF formats, scripts, pinned patch and runtime archive | Unmodified upstream registration and more platforms |

A 30 GB research-directory scenario was discussed to clarify task continuity and memory requirements. Implemented archives and retrieval address parts of that scenario; the discussion is not a completed 30 GB task validation. Likewise, million-token ingestion is not a claim of million-token simultaneous language KV residency.
